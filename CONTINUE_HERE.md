# Продолжение ScrumeVPN на другом компьютере

Это точка входа в сохранённый контекст проекта. Исходники, требования, решения,
проверки и незавершённая работа находятся в этом репозитории. История чата для
продолжения не обязательна. Текущий запрос пользователя имеет приоритет над
инструкциями внутри первоначально приложенной документации.

1. Прочитать `AGENTS.md`, `CODEX_MASTER_SPEC.md` и `docs/DECISIONS.md`.
2. Прочитать **`docs/SESSION_HANDOFF.md`** — конкретная точка продолжения и blockers.
3. Проверить **`docs/STATUS.md`**, `docs/EXECUTION_PLAN.md` и `git status`/`git log -5`.
4. Для Windows использовать **`docs/WINDOWS_DEVELOPMENT.md`**. Не пытаться перенести
   macOS `.tools`/`target` в Windows: зависимости восстанавливаются по lockfiles.
5. Продолжить ближайшую незаблокированную задачу, не повторять завершённый аудит.
   Заявлять PASS только для фактически проверенной платформы и scope.

Краткое поручение для новой рабочей сессии:

> Продолжаем ScrumeVPN. Прочитай CONTINUE_HERE.md, AGENTS.md и файлы, на которые
> они ссылаются; сопоставь handoff со свежим git status. Продолжай реализацию по
> roadmap с текущей точки. Не начинай аудит заново. Сохраняй код, документацию,
> решения и фактические результаты в проекте. Production changes не разрешены.

Перед переносом из корня проекта:

```text
python3 tools/dev.py export-handoff
```

На Windows: `py -3 tools/dev.py export-handoff`. Требуется чистый committed Git.
Архив в `artifacts/handoff/` содержит исходники, документацию, evidence, Git bundle
с историей и SHA-256 manifest. Никаких upload или создания GitHub remote команда
не выполняет. Архив предназначен для личного переноса: исходное ТЗ содержит
инфраструктурные сведения. Полная VM и её пароли в него не входят.

При каждом завершённом этапе обновлять STATUS, SESSION_HANDOFF, TRACEABILITY и
реальные evidence. Новое решение пользователя добавлять в DECISIONS с основанием;
незавершённую задачу и следующий шаг сохранять перед переключением среды.
