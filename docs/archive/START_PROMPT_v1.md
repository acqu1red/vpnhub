# Стартовый промпт для Codex

Открой этот репозиторий в VS Code/Codex. Ты выполняешь роль senior Rust/Tauri/Windows networking engineer, security reviewer и technical lead. Цель — реализовать поэтапно корпоративный ScrumeVPN Windows 10/11 x64 с настоящим Xray VLESS+REALITY TUN, отдельной службой SYSTEM, корпоративным issuer API и MSI-установщиком. Работаем преимущественно на macOS, Windows сборка/тесты — через GitHub Actions + настоящую Windows x64-машину.

**ПЕРВЫЙ ПРОХОД — ТОЛЬКО АНАЛИЗ, БЕЗ КОДА ПРОДУКТА.**

1. Прочитай `AGENTS.md`, `SPEC_ORIGINAL.md`, `CODEX_MASTER_SPEC.md` и все файлы `docs/`.
2. Сохрани различие между оригинальными требованиями клиента, его перепиской, предложенными уточнениями и неразрешёнными вопросами. Никогда не выдумывай решения за заказчика.
3. Открой и изучи актуальные на дату работы upstream репозитории, указанные в `docs/UPSTREAMS_AND_LICENSES.md`. Для каждого подтверди лицензию, статус сопровождения, релевантный код, совместимость с коммерческой проприетарной сборкой и наличие nested components. Код чужих VPN-клиентов с GPL не копировать.
4. Отдельно оцени, можно ли использовать `Shurubtsov/rustvpn` как набор компонентов; учти, что его базовая архитектура — SOCKS/HTTP sidecar без SYSTEM service + корпоративной учётки. Не переносить всё целиком без обоснования.
5. Сформируй `docs/TRACEABILITY.md`: каждое требование → источник → предлагаемая реализация → тест → статус.
6. Сформируй `docs/ARCHITECTURE.md` и 3 коротких ADR: (a) Xray native TUN vs custom Wintun FFI, (b) user DPAPI vs SYSTEM pre-login boot, (c) email OTP vs device-code/browser flow.
7. Сформируй `docs/EXECUTION_PLAN.md` с этапами G0–G12, зависимостями, mock/staging/prod boundaries, критериями готовности и финальным MSI.
8. Уточни конфликты в `docs/OPEN_DECISIONS.md`, особенно `sk-…` из `/verify`, подпись `expires_at`, источник `policy.json`, Windows 10 EOL, управление 20 устройствами.
9. Выведи письменный отчёт по шаблону: «что реально готово», «что можно переиспользовать», «что нет», «опасные места», «план первого POC», «какие решения нужны».
10. **Остановись.** Не запускать тесты на production, не запрашивать секреты, не вносить серверных правок, не создавать фальшивые готовые `.exe/.msi`.

После моего явного разрешения выполняй **только один следующий этап за раз**, добавляя unit tests/Windows CI при каждом важном изменении и честно сообщая, что реально проверено. Первый технический критический POC — Windows x64 service + настоящий Xray TUN + сохранение/восстановление DNS/routes, с исключительно тестовыми учётными данными.
