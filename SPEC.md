# Корпоративный VPN-клиент — техническое задание (черновик v0.1)

Заказчик: ООО «СКРАМ ИНЖИНИРИНГ». Исполнитель: TBD.
Платформа: Windows 10/11 x64 (первая очередь). Android — вторая очередь, вне текущего объёма.

---

## 1. Рамки

Клиент для сотрудников: одна кнопка «Подключить», корпоративный бренд, настройки недоступны
пользователю и управляются администратором с сервера. Пользователь проходит вход по
корпоративной учётке; VPN-доступ выдаётся на устройство после успешного входа и отзывается
администратором без выезда к пользователю.

Вне объёма: серверная часть VPN и панель администратора (уже реализованы), мобильные платформы,
macOS/Linux.

## 2. Лицензионная база

| Компонент | Лицензия | Обязательства |
|---|---|---|
| Xray-core (движок) | MPL-2.0 | при правке файлов Xray — публикуются только изменённые файлы; текст лицензии в комплекте |
| wintun.dll (TUN-драйвер) | проприетарная лицензия WireGuard LLC | распространяется только вместе с ПО, использующим его через API `wintun.h`; не модифицировать, не переименовывать, текст лицензии приложить |
| Шелл, UI, иконки | собственность заказчика | чужие ассеты и знаки не используются |

Запрещено: брать код Amnezia / NekoRay / Throne / Hiddify / v2rayN (GPL-3.0 → обязанность
передать заказчику исходники всей производной работы), а также их логотипы и элементы UI.

## 3. Архитектура

```
┌──────────────────────────┐        named pipe         ┌──────────────────────────────┐
│ ScrumeVPN.exe (GUI,User) │ ◄───────────────────────► │ ScrumeVPNSvc (служба,SYSTEM) │
│ - трей, статус, кнопка   │   JSON-RPC, ACL by SID    │ - политика (чтение+проверка) │
│ - вход по SSO (браузер)  │                           │ - конфиг Xray (генерация)    │
│ - нет UI настроек        │                           │ - процесс Xray, TUN, DNS     │
└──────────────────────────┘                           └──────────────────────────────┘
                                                                │
                                             %ProgramData%\ScrumeVPN\policy.json (signed)
```

- **Служба** — единственный компонент с правами SYSTEM. Держит Xray-процесс, поднимает TUN,
  применяет политику. Пользователь не может остановить службу или изменить конфиг без прав
  локального администратора.
- **GUI** — без прав elevation, автозапуск в сессии пользователя (HKCU `Run`), трей,
  one-instance mutex. Служба не зависит от запущенного GUI: сессия поднимается при загрузке ОС.
- **Конфиг Xray** генерируется службой в память/защищённый файл и передаётся процессу через
  сокет/файл с ACL; в `%ProgramData%\ScrumeVPN\` пользователю доступ только на чтение.

## 4. Вход и выдача профиля — поверх существующего gw-issuer

Своей аутентификации не делаем. На scrume-ai уже работает выдача доступа по коду на почту
(`/opt/llm-gateway/issuer/gw_issuer.py`, слушает 4100, наружу через nginx gw.ailabscrume.ru).
Модель проверена на агенте и переносится на VPN без изменения:

| Секрет | Где живёт | Время жизни |
|---|---|---|
| `sk-…` ключ LiteLLM | только на шлюзе | — |
| `at-…` зачисление (install_token) | машина сотрудника, DPAPI-конверт | долгоживущий, отзывается |
| `as-…` сессия | память клиента | 300 с, перевыпуск через `/app-key` |

Существующие эндпоинты (не меняются):

```
POST /request {"email"}                       → письмо с 6-значным кодом (TTL 600 с, 5 попыток, resend 60 с)
POST /verify  {"email","code"}                → {"ok":true,"key":"sk-…","install_token":"at-…"}
POST /app-key  X-Install-Token: at-…          → {"access_token":"as-…","expires_in":300}
POST /revoke  {"email"|"install_token"}       → {"ok":true,"revoked":N}   (только с 127.0.0.1)
```

Допущенные домены: `scrume.ru`, `mashkancev.ru` (+ одно исключение). Сотрудник должен быть
заведён в `employees.json` — иначе 404 «сотрудник не найден» (это же и есть «только свои»).

Добавляется один эндпоинт — выдача VPN-профиля по зачислению:

```
GET /vpn/profile
  X-Install-Token: at-…
→ { "ok": true,
    "profile": {
      "protocol": "vless",
      "server": "72.56.118.25", "port": 8443,
      "uuid": "<uuid этого зачисления>",
      "flow": "xtls-rprx-vision",
      "tls": { "type": "reality", "sni": "www.samsung.com", "fingerprint": "chrome",
               "public_key": "<pbk>", "short_id": "<sid>" },
      "network": "tcp",
      "dns": ["1.1.1.1", "8.8.8.8"], "mtu": 1400,
      "split_tunnel": { "mode": "exclude", "cidrs": [], "domains": [] }
    },
    "signature": "<ed25519 над canonical JSON профиля>",
    "expires_at": "..." }
```

Серверная часть под это (минимальный объём):

1. В эндпоинте `/vpn/profile` сгенерировать UUID (если его ещё нет у зачисления), добавить клиента
   в inbound `vless-reality` (tcp/8443) с `email = <alias>`, отдать профиль. Xray в работе уже
   поднят: `vless-reality`, `xtls-rprx-vision`, REALITY `dest www.samsung.com:443`,
   `serverNames [www.samsung.com, www.cloudflare.com]`, сейчас 4 клиента (oleg-01, phone, phone-alt, scrume-pc).
2. Включить API-inbound Xray на `127.0.0.1:10085` (HandlerService), чтобы добавлять/удалять
   клиента без рестарта службы — иначе каждый отзыв рвёт все соединения.
3. Расширить `/revoke`: помимо сессий и зачислений удалять клиента из Xray по `email`.
4. Подпись профиля — Ed25519, публичный ключ вшит в клиент.

Хранение на клиенте: `at-…` — DPAPI (per-user, `CryptProtectData`), профиль и политика —
файлы в `%ProgramData%\ScrumeVPN\`, писать может только служба.

Важно: UUID выдаётся на зачисление, а не на человека — если на машине переустановили систему,
старый `at-…` теряется и создаётся новое зачисление со своим UUID; старый отзывается админом.


## 5. Политика и «скрытые настройки»

Настроек в GUI нет по построению: статус, кнопка подключения, «Сменить учётную запись», «Выход».

Управление — администратором через сервер:
- серверы, протокол, split-tunnel, DNS, MTU — в подписанном профиле;
- параметры поведения (kill-switch, автоподключение при загрузке, частота проверки профиля) — в `policy.json`;
- изменение вступает в силу после рестарта службы или по событию проверки (не реже 1 раза в 24 ч,
  по умолчанию 6 ч), принудительно — командой администратора в панели.

Подпись Ed25519, публичный ключ вшит в бинарник. Политика без валидной подписи не применяется,
в этом случае клиент работает по последней валидной и логирует событие.

Граница возможного (фиксируется в договоре, а не замалчивается): локальный администратор на
машине пользователя может отключить службу, подменить бинарник, снять дамп трафика. Локальная
защита — снижение вероятности, а не гарантия; фактический контроль — серверный (ключ на
устройство, отзыв, подпись, журнал подключений).

## 6. Требования по пунктам

| Требование | Реализация |
|---|---|
| Брендинг | иконка приложения/трея/установщика, имя, экран входа — свои; UI без чужих элементов |
| Автозапуск | служба стартует с ОС (автоматически), GUI — HKCU Run; развёртывание MSI + GPO/Intune |
| Работа в трее | иконка со статусом (подключено/нет/ошибка), меню: Подключить/Отключить, Открыть, Выход |
| Скрытые настройки | отсутствует UI настроек; профиль и политика с сервера, подписаны |
| Смена конфига администратором | через панель/API, не правкой файлов на машине; применяется службой |
| Вход по корпоративной учётке | device code flow, системный браузер; пароль клиент не видит |

## 7. Стек

- Ядро (auth, разбор профиля, проверка подписи, split-tunnel, логи) — Rust, отдельный крейт,
  без Windows-зависимостей в бизнес-логике.
- Windows-шелл — Tauri 2 (Apache-2.0): трей, автозапуск, MSI, размер ~10 МБ.
- Служба — Rust-бинарь через `windows-service` + `wintun` через FFI (API `wintun.h`).
- Движок — Xray-core, релизный бинарь от апстрима, конфиг генерируется службой.
- Android (вторая очередь) — Kotlin + `VpnService` + Xray-core (gomobile), переиспользуется
  контракт API и формат профиля; Rust-крейт переиспользуется частично. Полного переиспользования
  UI не будет — это осознанное решение, не обещание «одного кода на всё».

## 8. Этапы

1. **Каркас (нед.)**: служба + GUI, IPC, трей, автозапуск, MSI; подключение-заглушка.
2. **Вход и профиль (1–1.5 нед.)**: device code flow, хранение токена, загрузка и проверка
   подписанного профиля, экран состояния и ошибок.
3. **Туннель (1–1.5 нед.)**: Xray под службой, wintun, DNS, split-tunnel, kill-switch.
4. **Администрирование и приёмка (1 нед.)**: применение политики, отзыв, журнал, тесты на
   чистых машинах, установка без прав администратора у пользователя.

Итого 4–5 недель одного разработчика. Подпись кода (OV/EV сертификат) заказывается на этапе 1 —
без неё SmartScreen блокирует установку у сотрудников.

## 9. Открытые вопросы

1. Протокол — **VLESS + REALITY, решено**. Сервер уже поднят (tcp/8443, xray active).
2. Закрытый контур: нужно ли гнать `at-…` не на машину пользователя, а в TPM/машинный сертификат
   (для машин домена) — влияет только на способ хранения, контракт не меняется.
3. Нужен ли kill-switch в первой очереди (влияет на поведение при падении Xray).
4. Разрешать ли пользователю обход VPN для локальной сети (принтеры, NAS) — обычно да, списком CIDR.
